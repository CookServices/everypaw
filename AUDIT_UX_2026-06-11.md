# Rapport d'Analyse UX — Everypaw (pages authentifiées)
**Date :** 2026-06-11
**Objectif :** Audit UX des pages une fois authentifié (conversion + rétention)
**Compte test :** test-print-multi@yopmail.com (plan Print, 3 crédits, 4 animaux)
**Pages auditées :** Dashboard (mode "Tous mes animaux" + mode pet sélectionné), Page animal (Journal / Histoires / Étapes / Foyer), Commande livre (steps 1-2), Bibliothèque, Paramètres, Modale Suggestion, Nouvel animal, Upgrade — desktop 1440px + mobile 390px

## 1. RÉSUMÉ EXÉCUTIF
- **[CRITIQUE — conversion]** La page Upgrade affiche "Plan actuel" sur la carte GRATUIT alors que le compte est Premium Print, avec les boutons "Commencer Digital/Print" actifs → risque de double souscription Stripe et perte de confiance totale sur la page de vente.
- **[CRITIQUE — navigation]** En mode "Tous mes animaux", 4 liens majeurs du dashboard ("Commander", "Voir les chapitres précédents", "Voir tout le journal" ×2) pointent vers un animal supprimé (`1f1785c8…`) → page "Animal introuvable". Les CTA principaux du hub sont morts.
- **[CRITIQUE — conversion]** Step Adresse de la commande livre : l'utilisateur avec crédit voit "Livre 28 €" dans le total sans ligne de remise crédit, à côté de "1 crédit utilisé · reste 2" et "~29 €" — trois informations de prix contradictoires au moment de payer.
- **[MAJEUR — rétention]** Gamification cassée : 0/9 étapes débloquées malgré un journal rempli de "bain", "vétérinaire", "anniversaire" ; hints de keywords qui ne matchent pas les mots naturels et un keyword anglais ("birthday") affiché en français.
- **[MAJEUR — onboarding/mobile]** Les toasts d'onboarding (×2 simultanés) recouvrent le composer du journal sur mobile : l'action cœur du produit (ajouter un moment) est bloquée tant qu'on ne les ferme pas.

## 2. DASHBOARD

### Points forts
- Hiérarchie claire : animaux → mois en cours → livre → question de la semaine → moments récents.
- Tuile "PROCHAIN CHAPITRE IA dans 20 jours · Généré automatiquement" : excellente mécanique d'anticipation.
- "QUESTION DE LA SEMAINE" : très bon prompt de rétention hebdomadaire.
- Skeleton shimmer sur les loading states.

### Problèmes identifiés

**[CRITIQUE] Liens du dashboard vers un animal supprimé (mode "Tous mes animaux")**
- "Voir les chapitres précédents", "Commander" (VOTRE LIVRE 2026), "Voir tout le journal" (×2) pointent vers `/dashboard/pets/1f1785c8-da7d-41af-8231-cc4566721108` qui n'existe plus → "Animal introuvable." + erreur 406 console. L'id provient probablement d'un `selectedPetId` persisté (localStorage) jamais validé.
- **Fix :** au chargement du dashboard, valider l'id persisté contre la liste des pets chargés ; si absent, retomber sur le premier pet et purger la valeur stockée. Ne jamais rendre un lien avec un pet id non présent dans `pets[]`.

**[MAJEUR] Mode "Tous mes animaux" : sections mono-animal non identifiées**
- Les cartes VOTRE MOIS / VOTRE LIVRE 2026 / QUESTION DE LA SEMAINE concernent en réalité UN seul animal, sans l'afficher. Résultat : "Quel est le superpouvoir de ?" (nom manquant), stats ambiguës.
- **Fix :** en mode agrégé, afficher le nom + avatar de l'animal concerné sur chaque carte, ou agréger réellement (somme des entrées, prochain chapitre le plus proche). Pour la question : interpoler le nom du pet ciblé ou reformuler sans nom ("de votre animal").

**[MAJEUR] 4e animal inaccessible depuis la grille**
- La grille montre 3 chips + "+1" non cliquable. "Ugg" n'est atteignable que via le sélecteur sidebar.
- **Fix :** rendre "+1" cliquable (ouvre le sélecteur) ou afficher tous les animaux avec wrap.

**[MOYEN] Doublon "VOTRE LIVRE 2026" avec statuts contradictoires (mode pet sélectionné)**
- Deux blocs successifs portent le même titre : la carte ("En cours de création ✦ · Commander") puis le BookProgressWidget ("Ton livre est prêt à être imprimé ✨ · Voir mon livre"). Statuts opposés, deux CTA vers la même page.
- **Fix :** fusionner en un seul bloc ; un seul statut calculé, un seul CTA.

**[MOYEN] État sélecteur incohérent**
- Drawer mobile affiche "Tous mes animaux" alors que toutes les sections du dashboard ciblent Coco.
- **Fix :** une seule source de vérité pour le pet sélectionné, lue par le sélecteur ET les sections.

**[MOYEN] Pluriels cassés partout**
- "1 entrées ce mois", "3 crédit disponible", "1 moment(s) ce mois", "chapitre(s)".
- **Fix :** helper `plural(n, "entrée")` appliqué aux compteurs ; bannir "(s)".

**[MINEUR] "∞ ✦ Premium" cryptique**
- Sous la barre de progression journal, sans explication.
- **Fix :** "Entrées illimitées (Premium)" ou tooltip.

## 3. PAGE ANIMAL — JOURNAL

### Points forts
- Composer en haut, placeholder personnalisé ("Qu'a fait Coco aujourd'hui ?"), date par défaut aujourd'hui.
- Timeline groupée par mois, dates ordinales, emojis d'humeur.
- Filtres année/mois.

### Problèmes identifiés

**[MAJEUR] Toasts d'onboarding empilés qui masquent le composer (mobile)**
- Deux toasts simultanés ("📖 Ton livre prend forme" + "🎁 Tu as un livre offert !") avec le même CTA cible (/order). Sur mobile ils recouvrent le textarea, le champ date et les boutons "Ajouter un moment" / "Générer l'histoire". Sur desktop ils persistent de page en page.
- **Fix :** file d'attente — 1 toast max à l'affichage ; sur mobile, position top ou bannière inline sous les tabs ; auto-dismiss après action ou 10 s ; dédupliquer les 2 messages livre en un seul ("Ton livre offert t'attend — configure-le").

**[MOYEN] Tutoiement / vouvoiement mélangés**
- Toasts et Foyer tutoient ("Ton livre", "Invite ton partenaire"), tout le reste vouvoie ("Vos animaux", "Recevez un email").
- **Fix :** uniformiser (vouvoiement recommandé, déjà majoritaire) dans `messages/fr.json`.

**[MINEUR] "Né(e) en décembre 2019"**
- "(e)" paresseux, tronqué sur mobile ("décembr…").
- **Fix :** utiliser le sexe si connu, sinon "Depuis décembre 2019".

**[MINEUR] H1 dupliqué**
- "Coco" en titre de page + "Coco" dans la card profil, deux `h1`.
- **Fix :** un seul `h1`, le second en `h2`/`p`.

## 4. PAGE ANIMAL — HISTOIRES

### Points forts
- Bandeau d'état parfait : "✓ Chapitre de juin généré · Prochain : 1er juillet (dans 20j) · Généré automatiquement".
- Pills d'humeur ("💝 Tendre"), périodes couvertes, pagination "Charger plus".

### Problèmes identifiés

**[MAJEUR] Numérotation des chapitres inversée**
- Onglet Histoires : "Chapitre 1" = le plus récent, "Chapitre 24" = le plus ancien. Conséquence sur la page commande : l'en-tête "CHAPITRE 1" contient le titre "Chapitre 24 — La vie de Coco". Dans le livre imprimé, la numérotation du titre contredira l'ordre réel.
- **Fix :** numéroter chronologiquement à la génération (1 = plus ancien) ; pour l'existant, migration de renumérotation ou affichage du numéro calculé plutôt que celui stocké dans le titre.

**[MOYEN] Bouton "✨ Générer l'histoire de Coco" ambigu quand le chapitre est déjà généré**
- Le bandeau dit "généré ✓ / prochain automatique", mais un gros CTA de génération manuelle reste actif juste en dessous.
- **Fix :** désactiver avec tooltip "Chapitre de juin déjà généré — prochain le 1er juillet", ou le masquer pour les plans premium en auto.

**[MINEUR] Double bouton de partage aux libellés flous**
- "Partager ce chapitre" + "Partager ce moment" côte à côte sur chaque chapitre, différence incompréhensible.
- **Fix :** libellés explicites : "Partager le texte" / "Créer une carte image", ou un seul bouton ouvrant la modale share-card avec options.

## 5. PAGE ANIMAL — ÉTAPES

### Problèmes identifiés

**[MAJEUR] Détection des étapes inopérante sur l'historique**
- 0/9 débloquées alors que le journal contient "Bain de Coco", "Visite chez le vétérinaire" (×2), "Premier anniversaire". La détection ne tourne qu'à la création d'entrée ; toute entrée passée (ou importée) ne compte jamais.
- **Fix :** rescan des entrées existantes au chargement de l'onglet Étapes (ou job one-shot), et enrichir `milestone_definitions.keywords` pour matcher les mots naturels : "bain" pour Premier bain (pas seulement "baignade"), "vétérinaire"/"véto", "parc"/"jardin", "promenade"/"balade"/"marche".

**[MAJEUR] Keyword anglais affiché en FR**
- "Anniversaire — Mentionnez "birthday" pour débloquer".
- **Fix :** keywords localisés par langue dans `milestone_definitions` (colonnes `keywords_fr`/`keywords_en` ou tableau jsonb par locale).

**[MOYEN] Hint faux pour "Premier souvenir capturé"**
- Affiche "Mentionnez "mémoire"" alors que la clé `first_memory` se débloque à la première entrée.
- **Fix :** hint dédié : "Se débloque à votre première entrée de journal".

**[MINEUR] Gamification plate**
- 0 % + 9 cadenas, aucune célébration, pas de prochaine étape suggérée.
- **Fix :** confetti/toast au déblocage (existant ?), mettre en avant "la plus proche" avec progression.

## 6. PAGE ANIMAL — FOYER

### Points forts
- Feature collaborative claire, limite "5 membres max" annoncée, état vide propre.

### Problèmes identifiés

**[MINEUR] Tutoiement isolé + pas de mention des droits**
- "Invite ton partenaire…" ; aucun détail sur ce que le membre pourra faire (lire ? écrire ? commander ?).
- **Fix :** vouvoyer + une ligne "Les membres peuvent ajouter des moments au journal".

## 7. COMMANDE LIVRE (/order)

### Points forts
- Stepper 3 étapes clair, aperçu 3D de couverture, personnalisation thème/titre, sélection de chapitres avec mise en page par chapitre, validation inline "Champ requis" par champ, info crédit présente.

### Problèmes identifiés

**[CRITIQUE] Step Adresse : prix contradictoires malgré le crédit**
- Même écran : "28 €" (gros), "~29 € + livraison" (ligne produit), "1 crédit utilisé · reste 2" (pill), TOTAL ESTIMÉ "Livre 28 € + Livraison ~5–10 €". Aucune ligne de déduction du crédit → l'utilisateur Print croit payer le livre qu'il a déjà payé via l'abonnement. Friction majeure à l'étape la plus chaude du funnel.
- **Fix :** quand un crédit s'applique : "Livre 28 € / Crédit Print −28 € / **Livre offert : 0 €** / Livraison X €". Supprimer le "~29 €" de la ligne produit (source de prix unique).

**[MOYEN] Livraison "~5–10 €" vague au moment de payer**
- **Fix :** quote Gelato réelle dès que le pays est choisi (il est prérempli France) ; afficher le montant exact avant "Continuer vers le paiement".

**[MOYEN] Step 1 : 4 CTA sans hiérarchie**
- "Commander un livre" / "Aperçu complet du livre" / "Télécharger le PDF" / "Sauvegarder" empilés.
- **Fix :** primaire = Commander ; Aperçu/PDF/Sauvegarder en boutons secondaires groupés (ou auto-save + menu "⋯").

**[MOYEN] Layout "▣ Photo" sélectionnable avec 0 photos**
- Le pet n'a aucune photo ; choisir un layout photo produira des pages vides.
- **Fix :** désactiver les layouts photo si 0 photo dans la période, tooltip "Ajoutez des photos dans le journal".

**[MINEUR] "ANNÉE DU LIVRE : Toutes les années" → "36 mois d'histoires"**
- Le libellé "année" contredit un livre multi-années.
- **Fix :** renommer "Période du livre".

## 8. BIBLIOTHÈQUE

### Points forts
- Distinction commandes passées / brouillons, "Recommander" avec startStep=address (excellent réachat), facture ou "Inclus dans votre abonnement Print" affiché, "Dupliquer en brouillon".

### Problèmes identifiés

**[MINEUR] "BROUILLONS 2/15 BROUILLONS MAXIMUMS"**
- Grammaire + redondance ; "chapitre(s)".
- **Fix :** "Brouillons (2/15)" ; pluriels gérés.

## 9. PARAMÈTRES

### Points forts
- Email actuel affiché, gestion abonnement contextuelle, code cadeau, export RGPD (HTML + JSON), zone dangereuse isolée.

### Problèmes identifiés

**[MAJEUR] Aucun accès au portail de facturation Stripe**
- Impossible de mettre à jour sa carte ou voir ses factures. La bannière dunning (`payment_past_due`) renvoie vers cette page → cul-de-sac précisément pour l'utilisateur qui doit corriger son moyen de paiement.
- **Fix :** bouton "Gérer le paiement et les factures" → `POST /api/stripe/portal` (Billing Portal session). Indispensable pour clore le dunning flow.

**[MAJEUR] Crédits livre invisibles**
- Le compte a 3 crédits ; la section abonnement dit seulement "Votre livre offert n'a pas encore été commandé" (faux d'ailleurs : 1 livre déjà commandé en avril, et il reste 3 crédits).
- **Fix :** afficher "🎁 3 crédits livre disponibles" + CTA "Commander un livre" dans Mon abonnement.

**[MOYEN] Downgrade sans explication des conséquences**
- Bouton "Premium Digital, 4,99 €/mois" direct.
- **Fix :** modale de confirmation : ce qui est perdu (livre annuel inclus, crédits restants ?), date d'effet.

**[MOYEN] Pas de préférence de langue**
- `profiles.language` existe désormais côté serveur mais aucune UI pour la changer.
- **Fix :** select Français/English dans Paramètres, écrit dans `profiles.language`.

**[MOYEN] Un seul toggle email pour 5+ types d'emails**
- Rappels hebdo seulement ; on-this-day, anniversaire, streak, prompts quotidiens, rétention n'ont pas d'opt-out ici.
- **Fix :** section "Emails" avec toggles par catégorie (ou au minimum un toggle "Emails souvenirs & rappels" global).

## 10. UPGRADE (/dashboard/upgrade)

### Problèmes identifiés

**[CRITIQUE] Plan actuel non détecté**
- Compte Premium Print → la carte GRATUIT porte le badge "Plan actuel", "Commencer Digital" et "Commencer Print" sont actifs. Risque : double souscription Stripe, et n'importe quel user payant qui arrive ici croit que son abonnement a sauté.
- **Fix :** charger `GET /api/stripe/subscription` au mount ; badge "Plan actuel" sur la bonne carte ; remplacer le CTA du plan détenu par "Plan actuel" (disabled) et les autres par "Changer de formule" → `/api/stripe/upgrade`.

**[MAJEUR] "$0/mois" sur page FR**
- Devise dollar sur la carte gratuite, euros partout ailleurs.
- **Fix :** "0 €" selon locale (probable clé i18n hardcodée).

**[MOYEN] Prix livre à la carte incohérent**
- 29 € ici, 28 € au step adresse, "~29 €" sur la ligne produit.
- **Fix :** constante de prix unique (lue des Stripe Prices) affichée partout.

## 11. OPPORTUNITÉS DE CONVERSION
- **Upgrade page cassée = priorité absolue** (cf. ci-dessus) : c'est la page de monétisation.
- **Crédit non valorisé au checkout** : afficher "0 €" transforme la commande du livre offert en moment de plaisir ("inclus dans votre abonnement") au lieu d'une suspicion de double facturation.
- **Settings** : la section abonnement Print ne pousse jamais le réachat "livre supplémentaire 29 €" alors que la bibliothèque le fait via "Recommander". Ajouter un CTA "Commander un exemplaire supplémentaire".
- **Pas d'upsell multi-pets** : le compte a 4 animaux mais le dashboard ne suggère jamais un livre pour Zigzag/Nemo ("Zigzag a 12 chapitres — créez son livre").

## 12. RÉTENTION — MÉCANIQUES MANQUANTES
- **Étapes cassées** = la boucle de gamification principale ne tourne pas (cf. §5).
- **Streak/regularité** : "1 moment ce mois" sans objectif ; ajouter un objectif doux ("3 moments ce mois pour un chapitre riche") relié à la barre de progression.
- **Question de la semaine** : après réponse, la carte affiche la réponse brute ("dvdvvdvd") sans label ni lien vers l'entrée créée. Afficher "Votre réponse ✓" + lien.
- **Pas de notification in-app du chapitre généré** : le badge "Nouveau chapitre disponible" sur la grille est bien, mais rien ne célèbre la sortie du chapitre (email on-this-day existe ; pas de moment "wow" in-app).

## 13. ACCESSIBILITÉ & TECHNIQUE
- **i18n** : keyword "birthday" en FR, "$0/mois", pluriels "(s)", tutoiement/vouvoiement mixte.
- **A11y** : deux `h1` sur la page animal ; toasts en `role=status` qui contiennent des CTA (un lecteur d'écran peut les rater) ; boutons "···" sans label explicite (aria-label "Options de l'entrée" manquant).
- **Erreur console** : 406 PostgREST sur pet inexistant (fetch `.single()` non guardé).
- **Mobile** : toasts recouvrent le composer (cf. §3) ; "Né(e) en décembr…" tronqué ; le reste du responsive est solide (drawer, pills, cards).

## 15. MÉTRIQUES SUGGÉRÉES À TRACKER
- **Conversion** : visites /upgrade → checkout démarré → payé (par plan) ; taux de commande du livre offert chez les abonnés Print (< 100 % = crédits dormants = churn risk) ; abandon par step du funnel commande (1→2→3).
- **Activation** : délai signup → 1re entrée ; signup → 1er chapitre généré ; % comptes avec ≥ 3 entrées à J7.
- **Rétention** : WAU/MAU ; % users répondant à la question de la semaine ; taux d'ouverture/clic des emails cron (weekly-reminder, on-this-day) ; % comptes avec ≥ 1 étape débloquée (santé gamification).
- **Viralité** : partages share-card par user ; invitations Foyer envoyées/acceptées ; rédemptions cadeaux.
